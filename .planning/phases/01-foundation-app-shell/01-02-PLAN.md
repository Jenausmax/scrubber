<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| main ↔ disk | `secrets.bin` (зашифрованный) и `config.json` (открытый) в `app.getPath('userData')`. Untrusted, если злоумышленник имеет file-system access под пользователем. |
| renderer → preload → main (IPC) | renderer передаёт `apiKey` строкой в main через `ipcRenderer.invoke`. Untrusted на стороне main: типа аргументов нужно валидировать (D-14). |
| main ↔ OS keyring (safeStorage) | OS-managed; trust зависит от backend (libsecret/kwallet/keychain/dpapi/basic_text). На basic_text trust degrades — D-07. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01 | Elevation of Privilege / Tampering | `ipcMain.handle('settings:saveApiKey', ...)` — renderer compromise → произвольный invoke | mitigate | D-08 + D-14: preload — единственный путь, allow-list через `Channels.*`. В handler — `typeof key === 'string' && key.length > 0`, иначе Result-fail (Pattern 2 V5 ASVS). Handler возвращает только Result, не value (Pitfall #7). |
| T-02 | Information Disclosure | API-ключ протекает в logs / renderer / на диск plaintext | mitigate | D-04/D-05: `hasApiKey` возвращает только `boolean`, не сам ключ. На диск пишется ТОЛЬКО `safeStorage.encryptString` → base64 (Pitfall #6). В renderer ключ никогда не отдаётся. Логи main: `console.error(err)` без объекта args. |
| T-03 | Information Disclosure (Linux deg.) | `safeStorage.getSelectedStorageBackend() === 'basic_text'` → реальное шифрование отсутствует | mitigate | D-07 + SHELL-03: SecretsStore детектит backend и переходит в memory-only режим — на диск НИЧЕГО не пишется. UI-баннер появится в Plan 04. |
| T-02-SC | Tampering | npm-пакеты `electron-store@11.0.2` | mitigate | Package legitimacy: official `sindresorhus`-публикуемый пакет, упомянут в CLAUDE.md §Technology Stack. Версия зафиксирована. Никаких `[ASSUMED]`/`[SUS]` пакетов в этом плане. |
